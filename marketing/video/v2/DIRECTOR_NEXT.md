## 3. 镜头语言

画面主角是照片、资料包、产出的资料，不是标题。

使用同一个可连续定位的空间，至少形成四种明确景别：
1. 近处照片遮挡镜头、远处生活照片可见的广角场景；
2. 顺着讲座页序跟拍的中景；
3. AI ZIP 内部结构的特写；
4. 完整报告和归还生活相册的正面留白镜头。

同一 ZIP 的外形比例、纸层和材质跨镜头不变。改成薄而紧实的资料容器：钴蓝封套、可见纸边、轻微厚度。降低现在夸张的拉链牙、厚侧板和大投影，避免像玩具盒/硬盘广告。

保留深色基底、暖白纸张、钴蓝强调。明暗反差由真实图像和白色资料页产生，不靠整屏 glow。开头紧、抽离利落、包内展开第一次停顿、报告出现第二次停顿、结尾松开。不要全程高速运动。

字幕相对各镜头安排，不固定顶端大栏。重要文案位于 x=80..900、y=160..1560 的工作安全区；装饰可出框。此安全区是本片制作保守值，不是平台官方精确边界。每个时刻最多一个主句。英文字号不靠自动缩小解决长句，使用下面的短文案。

## 5. 动态实现

沿用现有 HyperFrames/GSAP/TypeScript/FFmpeg，不做新一轮技术选型。
- 为照片、ZIP、PDF、阅读说明和报告建立稳定对象 ID；跨镜头保留状态对应关系。
- 一个 22 秒主时间线，显式 seek(frame/60)，同时驱动镜头和对象。
- 不将八张已渲染 PNG 当成八个视频层来做推拉。
- 允许 CSS 3D；确有必要时允许一个局部 Three.js 场景，但它仍接受相同帧时钟和原渲染器，不新增另一套录屏管线。不要仅因技术名而添加依赖。
- 首次使用的字体、HTML images、CSS 背景 atlas 和 Canvas/WebGL 纹理全部显式 await load/decode。未就绪不能开始取帧。
- 图集不内联没有问题，但本地资源路径必须完整打包，不能依赖 owner 的绝对路径。
- 英文版所有主文案、资料结果和尾句真正英文；不是仅把 WorkBuddy 换成 ChatGPT。

## 6. 基础声音本轮就做

不再等静音动画全部定稿才开始设计节奏。

用本地原创/已有明确可用权利的音源，不开付费账户、不购买素材。无旁白。小音量音乐衬底配合以下声部：照片擦过、页序归位、纸包展开、递送、报告落定、相册释放。

前段略紧，中段两次有停顿的冲击，末段松开；少量与主动作同步的声音优于几十个点击声。不能用昂贵音乐/音频 API 作为推进条件。合成配乐不好听就用克制的节奏与音效，不换成企业 BGM。

保留静音版。解码确认有实际音轨且不削波；人工试听只能在真的听过时标 PASS。

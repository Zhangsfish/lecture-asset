## 1. 本轮确定什么

用户已认可四步主线，并要求加入可选动画教学、个人联系方式/主页入口、打赏。它们纳入计划，但不挤进主流程，不要求一次性实现。

本轮不提交 App Review、不公开发布、不签付费协议、不填写备案/税务身份、不接入真实支付。GitHub 文档是后续任务契约，不是已实现证据。

产品核心继续按 `SPEC.md` / `IMAGE_POLICY.md` / `SAFETY_AND_STORAGE.md` 执行。各地规则和证据见 [地区审查](REGIONAL_RELEASE_REVIEW_2026-10-02.md)。

## 2. UI/UX 合同

### 主干

| 场景 | 主要信息 | 唯一明显主操作 |
|---|---|---|
| 选择照片 | 照片网格、已选数量、最多 200；保留扫选 | 下一步：检查照片 |
| 检查选择 | 按最终拍摄时间顺序展示，可移除误选；处理不会删原图 | 开始整理 |
| 整理照片 | 简短状态、页数/进度、取消或恢复等必要动作 | 运行中不放无关 CTA |
| JPEG 已就绪 | 照片准备完成；保持原有显式阶段切换 | 下一步：生成 AI 资料包和 PDF |
| 生成文件 | 文字识别/文件生成的用户语言和进度 | 运行中不放无关 CTA |
| 文件就绪 | ZIP 为主，查看/分享 PDF 为次 | 保存 AI 资料包（ZIP） |
| ZIP 分享回报完成 | 用户需要自行检查外部文件 | 我已确认 ZIP 保存成功 |
| 清理相册 | 精确数量、Live Photo 动态未归档、iCloud 同步删除提醒 | 删除这批原照片，另经系统确认 |

“清除本次 App 工作文件（保留相册照片）”是最终收尾的**可见第二路径**，不得藏在默认折叠的 DisclosureGroup 里。推荐文案“保留相册照片，仅清除 App 内文件 / Keep Photos, Clear App Files”。它视觉上次于“保存 AI 资料包（ZIP）”，但在 archive-ready 最终状态必须无需展开即可发现；仍需单独确认，并明确会删除本次 App 的恢复文件/本地 JPEG/ZIP/PDF/OCR 等工作副本（以实际存在为准）、未外部保存的文件无法从 App 恢复、相册原照片不受影响。该动作绝不调用 PhotoKit 删除，也不暗示会释放 Photos 图库空间。

不要引入多余 landing page、四步可跳转 tab、复杂导航框架。四步是信息架构，不是要求重写四个 pipeline。

### 去掉测试 UI，不去掉安全

正常 Release UI 不显示像素、source/JPEG bytes、内存峰值、SHA、工程 phase、ready 后 raw OCR count、逐页 page diagnostics 和复制测量按钮。正常可显示“12/37”这类用户进度，不把一切计数都删除。

失败时：简短说明 + 重试；安全技术详情只在失败状态折叠呈现，不含照片内容、OCR、私有路径或 PHAsset IDs。底层 telemetry/checkpoint/validation 保留。

ZIP 校验、确切 ZIP 身份绑定、最终 asset 集、权限重检、外部保存确认、独立删除动作不得弱化。PDF 分享/关闭分享弹窗不应解锁删除。清理成功前不丢恢复文件。

### 附属入口

首页和权限说明页提供不抢主 CTA 的“关于与支持”入口。至少可查看本地使用说明与隐私说明，不需要 Photos 权限。不要为了显示 About 重建 ProcessingModel 或取消现有任务。

最终结构：使用教程 / 反馈与联系 / 个人主页 / 隐私说明 / 支持开发者（完成独立支付验收后才显示）。不加假按钮或“支付即将上线”。

## 3. 新手教程 — S05-B

先定主界面，再做与真实动作一致的 3–4 段本地示意动画：扫选 → 按拍摄时间整理 → ZIP 与 PDF → 保存确认后才可清理。

- 首次提供可立即跳过的轻提示/教程；以后从 About 重看。
- 恢复中的任务优先，不因未看教程阻塞或覆盖 retained job；升级用户不强制重看。
- 演示使用捆绑示意图/符号；不采样真实相册，不触发导出或删除，无网络视频/Lottie SDK依赖。
- Reduce Motion 使用静态分镜；VoiceOver、文字放大、无声浏览可理解；没有倒计时或必须播完。
- 不把权限、联系、评价、支付捆绑到“继续”。系统相册请求仅由用户显式动作触发。
- 本地教程已读标记若使用 UserDefaults，需要补入实际 Required Reason API 审计，不凭 UI 功能简单就漏报。

## 4. 联系方式 / 个人主页 — S05-B

只用 owner 明确批准的公开邮箱和准确 HTTPS 主页。未知时隐藏该行，禁止从 Git/Apple账号或其他记忆猜。首页原邮箱 footer 方案被统一 About 入口替代，不同时堆两处宣传。

邮箱：主动 mailto，提供复制邮箱的明确备用操作；不自动发送、不自动附上照片、OCR、日志、ID或设备资料。

主页：明确外链标识，用户点击后在系统外部浏览器打开；不做内嵌网页、登录、远程资讯流、自动预取、analytics 或 app 内通用浏览器。核对落地页内容；不能用普通个人页伪装未获准的外部支付导流。

隐私披露区分本地处理、用户主动支持邮件、网页托管方访问记录和系统分享目标。不承诺“一切场景绝无个人数据”。

## 5. 支持开发者 — 独立 S05-C，非本轮实现

技术路线选择：标准 Apple StoreKit 2 + consumable 一次性小额支持。它是本项目的统一实现方案，不是宣称所有地区法律都只允许这一种支付。

- 核心全部免费；不打赏也能完整使用；不出售文件额度/永久权限/会员，不发虚拟币，不提供订阅。
- 仅用户主动进入 About → 支持开发者；不在启动、导出或删除完成后弹打赏提示。
- 用中性“支持开发者”文案，说明自愿、不获得额外功能；不包装成慈善募捐或免税赠与。
- 不做微信/支付宝收款码、PayPal/Stripe/网页外部支付分支；不套用未经核实的个人赠与例外；不加第三方支付 SDK。
- 金额档位/product IDs 由 owner 在 commerce 阶段确认。界面显示 StoreKit Product.displayPrice，不硬编码人民币或汇率。
- 取消、pending/Ask to Buy、验证失败、断网和商品不可用不得显示成功；不能影响照片工作流。交易验证、幂等处理及 finish 等按当前 StoreKit 文档实现和测试。
- consumable 不伪装成可恢复的永久权益；没有有效购买不显示“已支持”。不自建收据服务器/通知后台，除非地区义务经核实并单独批准。

开启此任务之前：owner 明确授权商业配置；Paid Apps agreement / banking / tax / product availability 实际状态可核验；目标地区支付与年龄/家长同意要求已评估；需要公开的身份资料由 owner 自己在官方门户处理。现有 Admin API key 和 TestFlight 不等于这些前提完成。

首次 consumable 需和新 app version 同批提交审核。若放在首次免费版本之后，做后续版本即可；不可把未审核/不可用支付偷偷开启。

## 6. 四阶段执行和停止点

| 阶段 | 执行范围 | 最小验收与停止点 |
|---|---|---|
| S05-A / READY | 主流程 UI、About壳和本地文字帮助/隐私、manifest、网页与简中商店材料草稿 | focused CI/Release build/合成视觉证据；PR 等审；不做动画、StoreKit、外部支付、公开网页或商店提交 |
| S05-B / READY | 真实主界面已稳定后加入可跳过动画、批准的邮箱/主页；把“保留相册照片，仅清除 App 内文件”提升为可见第二收尾路径；完成 Privacy/Support public pages；真实截图 | 导航/恢复/首次教程/两条清理路径针对性测试；exact build 内部 TestFlight 和三张 owner 截图；无占位信息 |
| S05-C / BLOCKED_OWNER_COMMERCE | 独立 StoreKit 支持开发者模块 | StoreKit/sandbox 状态测试和地区复查；没有真实扣款测试授权不发起付费；单独 PR，不与核心大重构混合 |
| S05-D / BLOCKED_OWNER_RELEASE | owner选定地区、当前法规/年龄确认/账户状态、最终 metadata/build | 完成地区证据卡，owner批准 exact RC + storefront 列表后方可提交；公开发布仍按明确授权 |

S05-B/C 在启动前由 ChatGPT 发布自己的短任务；不能看到总框架就一次全部实施。S05-C 可在首次免费发布后做，需 owner 确定版本顺序，不作为 S05-A 的阻塞。

地区法律/Apple要求若确实强迫新增 runtime（例如地区年龄确认），建立单独最小任务：适用依据 → 变更范围 → iOS18兼容/权限与数据影响 → targeted tests → owner授权。不能用“UI-only”名义跳过，也不能直接加入服务器、定位或身份证采集。

## 7. 测试边界

UI 是运行时代码：必须测导航、权限状态、恢复优先级和危险动作接线；不是“只换 UI 所以不用测”。但不重跑 S04：

- 不要求 owner 重新选 100/200 张、不重复微信转移/破坏性相册删除。
- 复用已存在的 unit/safety tests，少量合成图片测试更改的 UI 和失败/取消状态。
- 不要求每个发布 PR 重跑全部历史 stage workflows；挑相关安全/契约回归，记录未运行项。
- 正常 Release 状态确认看不到遥测；要测试 Release，不只验证 Debug。
- A 不必等邮箱才能代码验收。确需内部 TestFlight preview 时，隐藏未配联系人/主页/打赏，明确这是内部 UI 预览而非最终 RC；继续使用已有、显式触发的 upload workflow，不默认自动上传。
- 最终 RC 安装/启动和三张 owner 视觉截图：selection（已有选择）/processing-archive/ready-save-cleanup。只做一轮视觉收尾，不重新压力 QA。

## 8. 需要 owner 的信息，不需要现在重解释历史

公开邮箱、准确个人主页 URL（或明确暂不展示）是 B 的内容输入。签约/银行/税务/备案/DSA公开地址由 owner 在官方门户处理；这里只记录状态和脱敏证据，不收集身份证号、住址证明或 `.p8`。

大陆优先是研究/准备顺序，不保证大陆一定可上架。若具体门槛阻塞，写清楚原因和可继续的开发工作；owner 决定处理该门槛还是调整首次地区。不得擅自改成美国/全球发布。
